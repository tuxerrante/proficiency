# v0.2 delivery retrospective

This records failures that changed the delivery process. It intentionally
focuses on repeatable controls rather than a chronological incident log.

| Failure or risk                                                                            | Root cause                                                                                                                | Guardrail added                                                                                     |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| The first release PR grew to 35 files and more than 5,000 changed lines                    | Architecture, report behavior, packaging, CI, and docs were implemented together                                          | `.github/skills/stacked-pr-delivery` defines dependency-safe stack boundaries and bottom-up merging |
| Squash-merging the stack caused repeated conflicts and dropped `.cache/` from `.gitignore` | Squash commits changed ancestry while `main` had advanced                                                                 | The stack skill requires repository-wide diffs against current `main` before and after merging      |
| E2E left a test server listening on ports 8080/6060                                        | The script killed a background shell rather than the actual server process                                                | E2E starts and tracks the server PID directly and checks for clean shutdown                         |
| E2E concurrency checks were noisy                                                          | The SQLite stress endpoint introduced unrelated request failures; timing thresholds allowed either flakes or false passes | Concurrency tests isolate suitable endpoints and keep the threshold below the sequential baseline   |
| Relative-only performance gates would be noisy on shared runners                           | Small scheduler variations could exceed percentage thresholds                                                             | Latency and throughput gates require both relative and absolute noise floors                        |
| Public reports could encode `null` or accept incomplete JSON                               | Exported writers/readers trusted manually constructed values                                                              | Report I/O normalizes stable arrays and validates required schema fields                            |
| CLI, package, and Action failures were indistinguishable                                   | All errors shared one process exit code                                                                                   | Gate failures use exit code 3 and persist the report before returning                               |
| A Docker Action could not reliably profile a localhost service                             | Container network isolation differs from the job runner namespace                                                         | The Marketplace Action is composite; the Docker image remains a separate deployment option          |
| Security checks failed late in CI                                                          | Go and dependencies carried current advisories; govulncheck was informational                                             | Go/dependencies were upgraded and govulncheck, Trivy, gosec, and CodeQL are blocking                |
| The immutable v0.2.0 release could not be retroactively listed in Marketplace              | Marketplace selection happens while publishing a release                                                                  | Releases are now prepared as editable drafts before human Marketplace publication                   |
| Draft release tag behavior was documented incorrectly during review                        | Review feedback was accepted before checking the remote tag                                                               | The release skill requires direct verification of tag and release state                             |
| `go install @v0.2.0` printed `dev`                                                         | `go install` cannot receive release workflow ldflags                                                                      | The CLI falls back to tagged Go module build information                                            |
| `uses: ...@v0` could download a nonexistent `v0` binary asset                              | The Action ref and binary release version were conflated                                                                  | `action.yml` defaults to a full immutable binary version while `v0` remains the movable Action ref  |
| The repository was described as OSS while using BSL 1.1                                    | Source availability was confused with OSI open source                                                                     | The project was relicensed to GitHub-recognized Apache-2.0                                          |
| Exact JSON greps made E2E sensitive to formatting                                          | Tests asserted pretty-print whitespace instead of semantics                                                               | JSON assertions tolerate whitespace; structural checks remain in Go tests                           |
| Release workflow and local commands could drift                                            | Archive build logic lived inline in YAML                                                                                  | `scripts/release/build-assets.sh` and `verify-assets.sh` are shared by CI and maintainers           |
